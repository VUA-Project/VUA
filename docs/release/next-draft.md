## 本次变化

- **实验性 VRChat 登录(设置 → 实验性,默认关闭)**:第一次打开先用平实的话说明风险——
  VRChat 的条款要求玩家自己保管账号凭据,第三方登录可能导致账号处理,最重可至封号,
  VUA 与 VRChat 公司无关;玩家接受后才能开启。登录在 VUA 内完成:用户名(或邮箱)加密码,
  再按 VRChat 的要求输入邮件验证码(可重新发送邮件)、验证器验证码或恢复码。默认只保存
  会话;另勾「记住密码」后,VRChat 结束会话时 VUA 可以自动重新登录。账号卡片显示显示名、
  头像缩略图与登录状态,支持「退出登录」和「忘记此账号」(清除本机全部相关数据)。
- **机密的保存与边界**:会话与记住的密码用 Windows 按用户加密(safeStorage)存放在独立
  文件里,仅主进程持有;Gateway 返回、任务记录、日志、诊断、崩溃报告和 AI 工具(MCP)
  输出里都不会出现机密,`vua_status` 最多读到两个布尔(开关、登录态)。对 VRChat 的请求
  标明 VUA 身份,保持少量并按 429/5xx 退避。
- **托管上传直接以登录状态开始**:玩家已在 VUA 登录时,托管上传开始前 VUA 把会话一次性
  交给打开的 Unity(仅当前 Windows 用户可读的短期文件,Editor 读取后立即删除),SDK 面板
  随后以登录状态启动;上传记录注明登录来源(VUA 会话 / 面板内登录)。未在 VUA 登录时保持
  原有流程。
- **上传核对**:上传成功后,发布页在上传记录旁显示该 Avatar 在 VRChat 上的状态——名称、
  发布状态、平台、更新时间,「已在 VRChat 上找到」或「还不在你的 Avatar 列表里」,可手动
  刷新;只保存核对所需字段,不保存其他账号数据。

## 验证边界与已知事项

实验性登录的 API 客户端、加密存储、Gateway 边界、SDK 会话交接文件与上传核对均有本地
mock 与单元测试覆盖。以下需要作者用真实账号验证,完成前不声称可用:邮件验证码登录、
Unity 的 SDK 面板直接处于登录状态、上传核对找到真实 Avatar("AMF test1",
`avtr_7ce0e209-6069-40c2-8b23-4e6c2dad389a`)、退出与忘记后本机不再留有会话和密码。
该功能明知并明示违反 VRChat 账号政策的风险,VRChat 可能随时对第三方登录做出处理。
